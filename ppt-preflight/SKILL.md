# PPT Preflight · 前期策划

> 来源：从 guizang-ppt-skill 的 Step 1（需求澄清）独立出来的前置 skill。
> 本 skill 不生成任何 HTML/CSS/图片，只产出结构化大纲。

## 这个 Skill 做什么

在动手做 PPT 之前，帮用户从一个模糊想法梳理出清晰的结构化大纲。核心价值：**想清楚再动手，避免做到一半发现方向错了**。

输入：用户给一个主题或模糊想法
输出：一份 `大纲-v1.md`，包含风格选定、受众分析、叙事弧大纲、页数规划、主题节奏、素材清单、硬约束

## 工作流

### Step 1 · 判断起点

- **用户已给完整大纲 + 图片/截图要求** → 直接跳到 Step 4 生成大纲-v1.md
- **用户只给了主题或模糊想法** → 从 Step 2 开始逐项澄清

### Step 2 · 7 问澄清

逐项问清楚后再动手。一次最多问 3 个问题，优先问会影响版式选择的关键问题（风格、受众、素材）。

| # | 问题 | 为什么要问 |
|---|------|-----------|
| 1 | **风格 A 还是 B？**（电子杂志风 / 瑞士国际主义风） | 必须先问，决定后续所有布局和主题选择 |
| 2 | **受众是谁？分享场景？**（行业内部 / 商业发布 / demo day / 私享会） | 决定语言风格和深度 |
| 3 | **分享时长？** | 15 分钟 ≈ 10 页，30 分钟 ≈ 20 页，45 分钟 ≈ 25-30 页 |
| 4 | **有没有原始素材？**（文档 / 数据 / 旧 PPT / 文章链接） | 有素材就基于素材，没有就帮他搭 |
| 5 | **有没有图片或截图？希望怎么处理？** | 决定图文版式、图片槽位、截图处理方式 |
| 6 | **想要哪套主题色？** | 杂志风 5 套 / 瑞士风 4 套，挑一 |
| 7 | **有没有硬约束？**（必须包含 XX 数据 / 不能出现 YY） | 避免返工 |

#### 风格选择参考（问题 1）

| 如果用户说... | 推荐风格 |
|---|---|
| "杂志感" / "人文" / "Monocle 风" / 不指定 | **A · 电子杂志风** |
| "瑞士风" / "Swiss Style" / "Helvetica" / "极简" / "网格" / "信息图" / "数据驱动" | **B · 瑞士国际主义风** |
| 内容是 AI 产品 / 技术 / 工程 / 数据汇报 | B 更合适 |
| 内容是行业观察 / 人文 / 故事 / 文化 | A 更合适 |
| 用户给了大量 KPI 数字 / 路线图 / 流程 | B 更合适 |
| 用户给了大量纪实照片 / 人文图片 | A 更合适 |

#### 主题色速查（问题 6）

**风格 A（电子杂志风）5 套**：
1. 墨水经典 — 通用/商业发布，默认选择
2. 靛蓝瓷 — 科技/研究/数据
3. 森林墨 — 自然/可持续/文化
4. 牛皮纸 — 怀旧/人文/文学
5. 沙丘 — 艺术/设计/创意

**风格 B（瑞士国际主义风）4 套**：
1. 克莱因蓝 IKB — 通用/AI/科技，最经典
2. 柠檬黄 — 年轻/运动/消费品
3. 柠檬绿 — 生态/健康/新兴科技
4. 安全橙 — 安全/工业/基础设施

详细色值见 `references/themes-reference.md`。

#### 图片约定（问题 5 涉及图片时告知用户）

- **文件夹位置**：`项目/XXX/ppt/images/` 下（和 `index.html` 同级）
- **命名规范**：`{页号}-{语义}.{ext}`，例如 `01-cover.jpg` / `03-figma.jpg` / `05-dashboard.png`
- **规格建议**：单张 ≥ 1600px 宽，JPG 用于照片/截图，PNG 用于透明 UI/图表
- **没图怎么办**：可以先用占位色块生成结构，等图片后期补

#### 截图需求约定（问题 5 涉及截图时必问）

- **截图位置**：截图文件在哪个文件夹？是否已命名？
- **使用目的**：保真展示 / 截图美化 / 截图再设计 / UI 情景图？
- **落位比例**：常用 `21:9` / `16:10` / `16:9` / `4:3` / `1:1`
- **内容要求**：是否必须保留全部文字、品牌、数据？是否有敏感信息要遮挡？

### Step 3 · 搭叙事弧大纲

用"叙事弧"模板搭骨架：

```
钩子(Hook)       → 1 页   : 抛一个反差 / 问题 / 硬数据让人停下来
定调(Context)    → 1-2 页 : 说明背景 / 你是谁 / 为什么讲这个
主体(Core)       → 3-5 页 : 核心内容，用不同布局穿插
转折(Shift)      → 1 页   : 打破预期 / 提出新观点
收束(Takeaway)   → 1-2 页 : 金句 / 悬念问题 / 行动建议
```

然后根据选定的风格，参考 `references/layouts-reference.md` 中的布局列表，为每一页分配合适的布局类型。

#### 主题节奏规划（必做）

每页必须标注主题 class：`light` / `dark` / `hero light` / `hero dark`。

**硬规则**：
- 连续 3 页以上同主题 = 视觉疲劳，不允许
- 8 页以上必须有 ≥1 个 `hero dark` + ≥1 个 `hero light`
- 整个 deck 不能只有 `light` 正文页，必须有 `dark` 正文页制造呼吸
- 每 3-4 页插入 1 个 hero 页（封面/幕封/问题/大引用）

### Step 4 · 输出大纲-v1.md

用以下模板输出最终大纲：

```markdown

- **主题色**：[名称]

## 素材清单
- [ ] 原始素材：[有/无，列出]
- [ ] 截图：[数量 + 处理要求 + 比例]
- [ ] 图片：[数量 + 来源 + 比例]

## 硬约束
- [列出所有硬性要求]

## 叙事弧大纲

| 页码 | 主题 | 布局 | 主题色 | 备注 |
|------|------|------|--------|------|
| 1 | [封面标题] | [布局名] | dark | — |
| 2 | [内容摘要] | [布局名] | light | — |
| ... | ... | ... | ... | ... |

## 主题节奏
```
[列出每页主题，如: dark → dark → light → hero dark → light → ...]
```
通过自检：[确认无连续 3 页同主题，含 hero 页数量达标]
```
