# Story Podcast Script Generator — 故事播客脚本生成

两阶段工作流：**故事素材 → 故事概述 → 播客对话脚本**。
将叙事性文本（故事、小说、叙事文）分割为多角色朗读的对话脚本，保留原文一字不改。

---

## 前置引导：收集需求

收到用户的故事素材后，**不要直接开始生成**。先通过对话引导用户确认以下配置：

1. **主持人/朗诵者人数**：几位说话者？（最少 1 位，建议 2-3 位）
   - 1 人：单人朗读模式
   - 2 人：双人交替朗读（推荐）
   - 3 人及以上：多人分角色朗读

2. **角色分配偏好**（可选）：
   - **自动分配**（默认）：按逻辑分组自动分配 speaker_id
   - **手动指定**：用户提供角色标签（如"叙述者"、"角色A"、"旁白"），系统按角色名映射 speaker_id

3. **语言**（可选）：中文 / 英文（默认与输入素材一致）

4. **其他定制**（可选）：特殊输出格式要求、是否保留源文本前缀标签等

**记录用户回答**，为后续流程使用。

---

## 阶段一：生成故事概述

从用户提供的原始故事素材中生成结构化概述。

### 执行步骤

1. **生成中间核心摘要（内部步骤）**
   - 仅基于故事正文内容（忽略标题和副标题），生成约 150 字符的核心观点摘要
   - 此摘要不显示在最终输出中，仅作为标题生成的基础

2. **生成标题**
   - 从核心摘要中提炼标题
   - 严格控制在 15-20 个字符之间
   - 采用"主标题：副标题"结构，使用全角冒号"："分隔
   - 作为最终输出的第一行

3. **生成标签**
   - 从故事正文中提取 3-5 个关键词
   - 用 `#` 符号分隔
   - 作为最终输出的第二行

### 输出格式

- **第一行**：标题（"主标题：副标题"）
- **第二行**：标签（#关键词1#关键词2#关键词3）
- **从第三行起**：Markdown 格式的摘要正文（使用 `##` / `###` 层级）
- 输出语言与原始输入语言相同
- **不**使用 markdown 代码块包裹

**详细约束**：参见 [references/overview-prompt.md](references/overview-prompt.md)

---

## 阶段二：生成播客对话脚本

基于阶段一生成的概述，以及引导阶段收集的配置（说话者人数、角色偏好），
将**原始故事文本**分割为多角色对话脚本。

### 核心规则

1. **保留原文，一字不改**
   - `"dialog"` 字段的内容必须是源内容的精确片段
   - 不能更改、摘要或重写原始文本

2. **文本分割**
   - 按自然标点符号（句号、问号、感叹号）或逻辑断点分割为完整句子
   - 分割后确保内容完整性：所有 dialog 拼接后应还原完整的原始内容

3. **说话者 ID 分配**
   - 如果源内容已有角色标签（如"叙述者："、"角色A："），按角色名映射 speaker_id（从 0 开始）
   - 如果没有角色标签，按逻辑分组自动分配：
     - **逻辑分组**：连续句子形成连贯思想时分配给同一 speaker_id
     - **说话者变化**：在主题或视角转变处切换说话者
     - **强制包含**：每位说话者至少分配一行对话

### 输出格式

纯 JSON 字符串，**不带** markdown 代码块包裹：

```json
{
  "podcast_transcripts": [
    { "speaker_id": 0, "dialog": "..." },
    { "speaker_id": 1, "dialog": "..." }
  ]
}
```

- 输出语言与源内容相同
- 不添加任何总结或结束语

**详细约束**：参见 [references/podscript-prompt.md](references/podscript-prompt.md)

---

## 执行顺序

0. **前置引导**：向用户提问，收集说话者人数、角色偏好、语言等配置
1. 完整执行**阶段一**，生成故事概述（标题 + 标签 + Markdown 摘要）
2. 将阶段一的输出和引导阶段的配置，加上**原始故事素材**，
   作为输入执行**阶段二**生成播客对话脚本
3. 最终向用户呈现：
   - 阶段一生成的故事概述
   - 阶段二生成的 JSON 播客脚本
