# Podcast Script Generator — 播客脚本生成

两阶段播客脚本生成工作流：**素材 → 结构化概述 → 播客对话脚本**。

---

## 前置引导：收集需求

收到用户素材后，**不要直接开始生成**。先通过对话引导用户确认以下配置，一次问完：

1. **概述模式**：内容概述用哪种方式？
   - **模式 A：深度摘要** — 严格忠实原文，生成客观全面的结构化摘要（适合信息密集的文章、报告、论文）
   - **模式 B：主题扩展** — 基于核心主题做逻辑丰富和趋势推导，不受"忠实原文"约束（适合短素材或需要发散讨论的场景）

2. **主持人人数**：几位主持人？（最少 1 位，建议 2-3 位）

3. **播客时长**：大致多长？
   - "5分钟以内" → 中文 800-1500 字
   - "8-15分钟" → 中文 3000-6000 字

4. **其他偏好**（可选）：发言风格（顺序轮流还是自由讨论）、角色设定（主持人身份、嘉宾风格）、语言（默认中文）。如用户未提及，按默认值执行。

**记录用户回答**，为后续流程使用。

---

## 阶段一：生成内容概述

从用户提供的原始素材中生成结构化概述，作为阶段二的输入。

### 字数判定

评估输入内容字数，自动选择对应模式。**如用户已在引导中指定了模式，优先遵循用户选择**。

| 条件 | 模式 | 行为 |
|------|------|------|
| ≥200 字 | **模式 A：深度摘要** | 忠实原文，生成客观全面的结构化摘要 |
| <200 字 | **模式 B：主题扩展** | 基于核心主题进行逻辑丰富和扩展（忽略"忠实原文"约束） |

### 元数据生成

在输出前两行，独立于正文摘要生成：

1. **标题**（第一行）：15-20字，"主标题：副标题"结构，用全角冒号"："分隔
   - 先生成约150字的中间核心摘要（仅从正文提取，不显示在输出中）
   - 再从中间核心摘要提炼标题
2. **标签**（第二行）：3-5个关键词，用`#`分隔，从正文提取

### 内容原则

**准确性**：严格忠实于源材料，避免主观推断，保留完整原意和语境。
**客观性**：中立公正地呈现信息，排除偏见和个人评论。
**全面性**：捕捉所有关键主题、核心论点和必要上下文。

### 输出格式

- 第一行：标题（"主标题：副标题"）
- 第二行：标签（#关键词1#关键词2#关键词3）
- 从第三行起：Markdown 格式的摘要正文
- 使用 `##` / `###` / `####` 层级，项目符号列表
- **不使用** markdown 代码块包裹（即不要 ```markdown ... ```）
- 专业客观的语调，清晰简洁的语言

**详细约束**：需更完整的原则说明、验证标准、长度指南时，参见 [references/overview-prompt.md](references/overview-prompt.md)

## 阶段二：生成播客脚本

基于阶段一生成的概述（含标题、标签、摘要），以及引导阶段收集的配置，生成 JSON 格式的播客对话脚本。

### 角色分配

- **Speaker 0**：主导主持人/协调者 — 引导对话、介绍环节、提出关键问题、总结要点
- **Speaker 1+**：联合主持人 — 从以下角色中按需分配互补角色：
  - 专家：提供深入的事实见解
  - 好奇新手：提出听众可能有的澄清性问题，充当听众代表
  - 实用怀疑论者：质疑假设，关注现实影响
  - 热情者：带来活力，分享个人轶事
- 每位说话者在整个脚本中必须保持一致的 voice 和观点
- **如用户在引导中指定了角色身份，优先遵循用户设定**

### 发言模式

- **顺序（sequential）**：固定重复顺序（0→1→2→0→1→2...）
- **随机（random）**：动态不可预测，模仿真实对话（可插话、连续短发言），但确保发言时间平衡分配

### 对话风格要求

- 使用缩略语、感叹词（"哦！"、"哇！"、"嗯"）、话语标记（"你知道"、"对吧？"）
- 说话者之间真正相互回应，建立在彼此观点之上
- 变化节奏：混合简短有力的台词和更长、更具解释性的台词
- 主导主持人使用清晰过渡连接不同主题

### 内容覆盖

- 确保阶段一概述中的**每个独特主题、关键事实**都在脚本中被引用
- **关键主题**：投入更多对话、示例和多人分析
- **次要主题**：快速供述、简要承认，确保包含但不打断流程

### 对话深化技巧

为避免过早结束话题，必须主动使用以下技巧：
- **后续与追问**：提出"能举个现实例子吗？""这对普通人意味着什么？"
- **示例与类比**：用丰富示例或生动类比解释核心概念
- **适度发散**：引导到相关领域的联想
- **辩论与对比**：从不同视角创建讨论
- **重述与总结**：在讨论间隙和主题结束时提供总结

### 长度控制

按目标时长对应字数：
- "5分钟以内"：中文 800-1500 字
- "8-15分钟"：中文 3000-6000 字

### 输出格式

纯 JSON 字符串，不带 markdown 代码块包裹：

```json
{
  "podcast_transcripts": [
    { "speaker_id": 0, "dialog": "..." },
    { "speaker_id": 1, "dialog": "..." }
  ]
}
```

**详细约束**：需完整的角色示例、互动示例、XML 格式指南时，参见 [references/podscript-prompt.md](references/podscript-prompt.md)

---

## 执行顺序

0. **前置引导**：向用户提问，收集概述模式、主持人人数、播客时长等配置
1. 完整执行**阶段一**，生成结构化概述
2. 将阶段一的输出作为"源内容"，加上引导阶段收集的配置，执行**阶段二**生成播客脚本
3. 最终向用户呈现阶段二生成的 JSON 播客脚本
